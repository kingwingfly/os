# Installed dash

`/usr/bin/dash` is a WASIX executable; `/usr/bin/sh` links to it. `/bin/sh` resolves through merged `/usr`. It uses ordinary exec authorization and filesystem operations. The browser shell does not dispatch its commands.

Build with `node scripts/build-shell.mjs --out-dir dist`. The normal web build also runs this recipe. Node, `tar`, a POSIX `sh` and its standard text tools are required. The builder downloads SHA-256-verified dash source, WASIX libc sysroot and WASI SDK 27; `lock.json` pins all inputs. Linux/macOS x86_64 and ARM64 SDK archives are listed; reproducibility is validated on Linux x86_64. Cache location defaults to `~/.cache/os/build`, overridable with `OS_BUILD_CACHE`. Each invocation extracts fresh source and compiles; no host clang or prebuilt shell is substituted. The optional PATH-discovered wasm-opt pass is explicitly disabled, so npm and direct invocations use the same pinned compiler output. Prefix maps, fixed locale/timezone/epoch and pinned generated source files remove local paths and timestamps from the image. Compare SHA-256 of two builds in separate output directories to verify it.

OS changes (2026-11-09–10):

- Build `bltin/printf.c` with `SHELL`, selecting dash's output buffers for redirections and pipes. The upstream WASIX make recipe compiled standalone printf instead.
- `platform.c` replaces stubbed C uid/gid/groups getters with authenticated process identity. Guest shells show `$`, root shells `#`; environment variables and later browser login/logout do not change a running process's credentials.
- `signals.c` supplies single-threaded `sigaction`, `signal`, `sigprocmask`, `pthread_sigmask`, `sigpending` and `sigsuspend` through generic host imports. The recipe removes only replaced signal objects from a private copy of the pinned libc archive. It never modifies the toolchain cache. Internal libc mask helpers use the same host state.
- The wait adapter uses `os.waitpid2` for signed process/group selectors and WNOHANG/WUNTRACED/WCONTINUED, and preserves EINTR through wait4. Dash uses its upstream SIGCHLD/sigsuspend loop. Stop/continue notifications do not reap children; exit status is consumed once. Resource-usage accounting remains unsupported.
- `platform.c` supplies authenticated session/group and terminal foreground-group functions. Interactive dash can manage nested jobs, recover its prompt after Ctrl+Z, and resume with `fg`/`bg`. Terminal input signals target its foreground group; background terminal reads stop with SIGTTIN and TOSTOP writes with SIGTTOU. A successful `setsid` detaches the controlling terminal without closing inherited descriptors.
- `platform.c` supplies POSIX `dup2` through WASIX descriptor duplication, retaining the source descriptor. The sysroot's preview-1 renumber implementation moves it.
- Its startup adapter registers filesystem preopens even when ordinary inherited descriptors precede them. The host preserves user fd 3 and gives a replacement root preopen a free descriptor below 1024 on exec. Our Rust tools use the same discovery rule through `os-posix`. Arbitrary uploaded modules whose libc assumes contiguous preopens can still require a platform rebuild.
- The host fixes NUL-inclusive `getcwd` sizing and supports this libc's counted exec argv/env, close-on-exec flags and default initial signal dispositions. These are ABI compatibility changes, not extra filesystem authority.

Signals 1–31 support default, ignored and caught dispositions; masks and pending standard signals coalesce. Fork copies dispositions/masks but not pending signals; exec resets caught handlers while retaining ignored dispositions and masks. Supported flags are SA_RESTART, SA_NODEFER and SA_RESETHAND. SIGKILL/SIGSTOP cannot be caught or blocked. Ctrl+C recovers an interactive shell, including after a running child. A caught/ignored SIGPIPE returns EPIPE when nothing was written; interrupted writes retain partial progress.

Delivery occurs at host calls and interruptible waits. There is no arbitrary instruction preemption for caught/blocked signals, real-time signal queue, thread signal routing, alternate signal stack, SA_SIGINFO metadata, or arbitrary controlling-terminal acquisition/reassignment (TIOCSCTTY/TIOCNOTTY). Persistent login/session supervision is still Phase 6.1 work; each browser pipeline currently receives a host-bootstrapped session. Unsupported action flags fail with EINVAL. Explicit SIGCHLD ignore does not yet implement automatic child reaping. Older uploaded libc images need the platform adapter for handlers/masks and C identity. Signal-aware modules use synchronous XHR because a callback cannot re-enter JSPI suspending imports across a JavaScript frame; other modules retain JSPI. Credentials and permissions remain server-enforced.

The image is raw WASM. The existing authorized compiler service transforms fork/setjmp support on first use and caches the result. This is a shared system image; private no-upload execution and local transformation are separate roadmap work.

The deployment includes `/usr/share/dash/` **HTTP assets** with `source.tar.gz` (the exact upstream source), this document, `lock.json`, `platform.c`, `signals.c`, `build-shell.mjs`, license notices and `build.json` (image digest). They are not yet mounted as VFS documentation. To rebuild from these assets, create `scripts/` and `packages/dash/`, put the recipe in `scripts/`, and the other text files in `packages/dash/`; run the command above. For offline source reuse, place `source.tar.gz` in the cache under its SHA-256 plus `.tar.gz`; downloaded SDK/sysroot archives use the same naming. Toolchain source: https://github.com/WebAssembly/wasi-sdk/tree/wasi-sdk-27 and https://github.com/wasix-org/wasix-libc/tree/2025b44a5d2eb22b64ecdbf1bb16f3e7699dfb60.
