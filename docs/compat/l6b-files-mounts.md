# L6b: Files (`/usr/bin/files`) and Mounts (`/usr/bin/mounts`) as Ordinary GUI Processes

Issue `#63` replaces the retired in-page Leptos/DOM Files window (`#window-files`, `crates/frontend/src/files.rs`) and Mounts manager (`#window-mounts`, `web/mount-manager.js`, `web/mount-sharing-ui.js`) with two ordinary unprivileged WASI GUI Document processes that communicate strictly over standard POSIX syscalls, `AF_UNIX` sockets (`SO_PEERCRED` + `SCM_RIGHTS`), and GUI v1 `/run/gui/seat0.sock`:

- **`/usr/bin/files`** (`crates/services/src/files.rs`, `crates/services/src/bin/files.rs`, bundle `/usr/share/gui/files/files.json`): Ordinary GUI v1 client presenting `SurfaceRole::Window` + `SurfaceKind::Document` (`app_id: "files"`). Browses the instance VFS directly via POSIX syscalls, persists `~/.config/os/files.json` (v1, §2.12), maintains a single-instance control socket `/run/user/<uid>/files.sock` (`0600`, `SO_PEERCRED`-checked), launches executables/previews/mounts via `/run/user/<uid>/desktop-actions.sock` and `/run/user/<uid>/terminal.sock`, and performs multi-file local uploads via compositor-mediated `PickFile` / `ExternalDrop` (`SCM_RIGHTS` read-only descriptors) or authorized cloud uploads (`UploadProgress`).
- **`/usr/bin/mounts`** (`crates/services/src/mounts.rs`, `crates/services/src/bin/mounts.rs`, bundle `/usr/share/gui/mounts/mounts.json`): Ordinary GUI v1 client presenting `SurfaceRole::Window` + `SurfaceKind::Document` (`app_id: "mounts"`). Talks directly to `mountd` and `exportd` over `AF_UNIX` with its own process `SO_PEERCRED` (including `SCM_RIGHTS` directory fd passing for `ExportRequest::Publish`), inspects POSIX mount modes and `manifest.json` via `os_posix::batch`, maintains a single-instance control socket `/run/user/<uid>/mounts.sock` (`0600`, `SO_PEERCRED`-checked), copies export addresses via `ClientReq::ClipboardWrite`, opens mounts in Files via `files.sock` / `desktop-actions.sock`, and exits cleanly on `CloseRequested` without detaching any user mounts.
- **UI-free programmatic facade (`web/mount-api.js`)**: Preserves `window.os.{shareMount,attachShared,detachShared,sharedMounts,revokeMount,exportStatus,mountTransports,localMounts,sharingDialog,localMountList,mountLocal,unmountLocal,activatePrivate}` with zero DOM/UI code; `localMounts(pane)` / `sharingDialog()` route to `window.osDesktop.openMounts(pane)` (`gui_mounts_focus`).

## Privilege & Isolation Invariants

1. **Zero `gui_*` Wasm imports or exports**: Neither `/usr/bin/files` nor `/usr/bin/mounts` imports or exports any `gui_*` host function (verified automatically in `tests/gui-protocol.test.mjs`).
2. **Unprivileged `SurfaceKind::Document` only**: `"files"` and `"mounts"` are removed from `compositor.rs`'s `SurfaceKind::Host` compat allowlist and `compat-bridge.js` / `crates/frontend/src/desktop.rs` `APPS` (leaving only `"viewer"` and `"editor"` for `#64` L6c). Any peer requesting `SurfaceKind::Host { component: "files" | "mounts" }` receives `EPERM`.
3. **Frozen syscall ABI**: Zero changes to `crates/abi/src/lib.rs` (74 variants verified by `node scripts/conformance/check-abi.mjs`) and zero new Cargo dependencies (`Cargo.lock` untouched).
4. **Sealed opaque Document frames**: Both bundles render inside `sandbox="allow-scripts"` `srcdoc` iframes with pinned SHA-256 CSP, opaque `'null'` origin, zero `window.os` / `fetch` access, and 4096-byte UTF-8 frame chunking (`os_services::gui_doc`).

## Compositor-Mediated Host Mount Consent (`ClientReq::MountConsent`)

Browser-only host grants (`window.showDirectoryPicker`, `FileSystemHandle.requestPermission`, OPFS/helper/share registration, and host capability discovery) cannot cross the opaque iframe boundary or be synthesized by an unprivileged WASI process. GUI v1 adds typed `ClientReq::MountConsent` / `DisplayCmd::MountConsent` / `InputEvent::MountConsentResult` / `ClientEvent::MountConsentResult` records:

- **`MountConsentAction::Capabilities {}`** (non-mutating): Requires an active unminimized seat without a blocking security modal (`can_input`) and probes host picker support (`typeof window.showDirectoryPicker === 'function'`), browser label, origin, relay readiness, and preloads saved IndexedDB handles on the Window host so later renewals run synchronously under user activation.
- **Mutating actions** (`PickHostFolder`, `RenewHostFolder`, `RegisterOpfs`, `RegisterHelper`, `RegisterShare`): Require focused surface ownership and a recent trusted user gesture (`gesture`, otherwise `EACCES`), allow at most one in-flight consent per seat (`EBUSY`), preserve pending consent across browser picker `HostFocus` blur, and cancel (`ECANCELED`) on `SeatActive(false)`, security modal, surface removal, or session/login change.
- **Host fencing**: `web/kernel/client.js` restricts `MountConsent` to the verified `/usr/bin/mounts` image owned by the active login UID (`gui_surface_binding` checks `uid`, `cloudAccess`, `isMounts`), binds each `request_id` to `(session, surface_id, owner_pid, endpoint)`, rejects forged `mount_consent_result` on `gui_host_event` and grant outcomes on `gui_mount_consent_result` (`EACCES`), and commits all grant registrations atomically inside the Worker (`gui_mount_consent_commit`) only while the originating session still matches. `compat-bridge.js` invokes `window.showDirectoryPicker` / `cached.handle.requestPermission` synchronously before any `await` and fences results against `os:login-changed` so late picker handles from a prior login are discarded without mounting.
- **Helper-mode policy**: `Canceled` and `Error` outcomes never switch Mounts into helper mode; only `MountConsentOutcome::Unsupported` (or `Capabilities { host_picker: false }`) enables the `os-local-helper` flow.

## Blind Window WebRTC Transport Broker

Because `RTCPeerConnection` is only available on the Window main thread (not inside Web Workers), `web/kernel/mount-services.js` calls `globalThis.openWindowMountTransport('connector' | 'listener', { p2p })` when `exportd` or `mountd` initiates a P2P/relay transport directly from `/usr/bin/mounts` or CLI tools (`exportctl`, `mount`). The dedicated client-kernel Worker requests a fresh opaque `MessagePort` from `web/kernel/page.js` (`mount-transport-open` -> `gui_mount_transport_port`, active on both `/` and `/shell.html`), which instantiates `mountListener` / `mountConnector` and transfers the raw framing port back to the Worker without exposing any relay credentials, ACLs, or filesystem handles to the page (falling back cleanly to Worker relay when no Window broker is registered).
