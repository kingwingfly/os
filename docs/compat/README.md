# L0a reference harness

This directory records measurements for [#46](https://github.com/kingwingfly/os/issues/46), step 1 of [#44](https://github.com/kingwingfly/os/issues/44). It does not select the architecture contract or change runtime behavior. Follow-up decisions belong to #47 and implementation belongs to the linked sub-issues.

The matrix contains 24 filesystem cases across five OS profiles and three process cases measured once independently of the filesystems. Filesystem rows compare normalized Linux and OS traces. Startup, GUI process visibility and browser-tab visibility are explicitly observational where this headless native fixture has no portable counterpart; their changes are checked, but they are not claimed to be compatibility differences that can automatically go stale. Every reviewed row names its follow-up issue; no permanent provider limitation is selected.

The reviewed counts and every changed row relative to `dcc9daa` are listed in [review changes](review-changes.md). The three process facts are stored once, not counted five times.

## Reproduce

From a fresh checkout on x86_64 Linux, install the repository's Rust targets and build tools as described in the main README, plus `unshare`, a Docker-compatible container engine, and Chromium's Playwright dependencies. Subordinate UID/GID mappings and `newuidmap`/`newgidmap` allow the Linux two-account case. The mount namespace uses `unshare -Urm`; `--map-auto` adds the mapped fixture IDs used by ACLs and the two creators.

```sh
npm ci
npm run setup
npx playwright install chromium
cargo xtask conformance --target linux
cargo xtask conformance --target os
cargo xtask conformance --check
```

The OS runner first rebuilds the current web assets with `cargo xtask build --web-only`, then builds the conformance WASI executable, Linux helper, and Worker in release mode. A stale or absent `dist/` cannot be used for a successful run. It reserves distinct unused server and inspector loopback ports together, creates a fresh Wrangler configuration, credentials and `--persist-to` state under `/tmp`, and uses fresh Playwright contexts. When using Podman, the runner owns a separate API service/socket with a separate image store under `~/.os-conformance-images` (override with `OS_CONFORMANCE_PODMAN_DIR`). The image-store directory must be owned by the current user, have mode 0700, and not be a symlink; this is checked before any image is loaded. Foreign or shared pre-created stores are rejected. An explicitly empty OS_CONFORMANCE_PODMAN_DIR is rejected before resolving or creating any path. Only images persist in this cache. Each run's Podman configuration sets `transient_store = true` with a runroot inside the run's own state directory, so container metadata, Podman's database and mount state are private to the run and never stored in the cache; a reboot or an interrupted run therefore leaves nothing in the cache that a later run reads, and concurrent runs do not share container state. Each run records its runner and every process group it starts (Podman service, server, helper), by PID and start time, in `run.json` in its state directory. A later run finds runs whose runner is gone, stops the groups whose leader is provably the recorded process, removes that run's containers through its private Podman metadata (`podman rm --all` against that run's storage configuration), and prints what it did. A live run, or a group whose leader has exited, is never signalled; the latter is reported. With Docker, the command that removes the interrupted run's labelled containers is printed instead. The temporary configuration uses the repository's real compiler container and relay; the unused archive container is omitted. No compiler transport interception is used. `OS_TEST_URL` from the calling shell is not used to connect to an existing instance. No seeding, existing credentials, demo directories or `.worktrees/` are used. The conformance executable is attached as a private executable file with explicit cloud delegation, then launched through the normal OS loader and process engine on every filesystem. It is not installed in the system image.


On this validation host, the default Podman store had inherited restrictive ACLs and rootless build networking could not resolve the package registry. The recorded run used the dedicated store and a prebuilt compiler made from the unchanged repository Dockerfile:

```sh
export OS_CONFORMANCE_PODMAN_DIR=/tmp/os-l0a-podman
node --input-type=module -e "import { imageStore } from './scripts/conformance/storage.mjs'; await imageStore(process.env.OS_CONFORMANCE_PODMAN_DIR);"
mkdir -p "$OS_CONFORMANCE_PODMAN_DIR/storage"
umask 022
podman --root "$OS_CONFORMANCE_PODMAN_DIR/storage" \
  --runroot "${XDG_RUNTIME_DIR:-/tmp}/os-conformance-podman-build" --transient-store --storage-driver overlay \
  --cgroup-manager=cgroupfs build --network host --layers \
  -f containers/compiler/Dockerfile -t localhost/os-conformance-compiler:baseline .
export OS_CONFORMANCE_COMPILER_IMAGE=localhost/os-conformance-compiler:baseline
```

The optional prebuilt-image path verifies `package.json`, the lockfile, every compiler source copied by the Dockerfile, and the locked Binaryen bytes against this checkout before starting Wrangler. It still uses the actual ModuleCompiler service, container transport, authorization and R2 transform cache. It does not redirect compilation requests to a standalone server. The image identity and verified hashes are in `evidence.json`. The default remains building the repository Dockerfile directly.

Successful runs remove their disposable state. A failed run prints its retained state/log directory for investigation. Linux preserves every complete stdout row in `observations.json` and command/status/stdout/stderr in `failure.json` even when the probe panics or a timing child cannot start; incomplete results are never published as a successful baseline. The OS retained-state notice runs inside cleanup before signal/exception termination can exit, and helper stderr goes to `server.log`. Cleanup targets the recorded owned processes/groups. After a group's leader exits, the runner watches the group and treats it as gone for good once it is seen empty, or once its number names a live process again, so a reused number is never signalled. Escalation is bounded: a group still present five seconds after SIGKILL (a member in uninterruptible I/O, or an unreaped zombie) fails cleanup with its surviving members listed, and everything acquired before it is kept, since it may still be in use; a failed stop can be retried. With Podman, the runner starts its own API service, in its own process group, on a socket inside the run's state directory. The Miniflare egress image is resolved before anything starts, and the run stops if it cannot be. One per-run Docker API proxy (`scripts/conformance/engine-proxy.mjs`) sits in front of the engine: it labels the containers this isolated Wrangler creates and, on Podman, drops the memory swappiness that crun refuses on cgroup v2. Cleanup removes only that label on Docker as well as Podman, preserving pre-existing and concurrently created unrelated containers. A DELETE answered with 404, or with 409 (removal already in progress, as for workerd's AutoRemove containers), is followed by listing again until no labelled container remains; one still listed after 30 seconds fails cleanup. TLS engine endpoints are verified against the engine's host name, never the forwarded Host header, and IPv6 endpoints are supported. Without `DOCKER_HOST`, the endpoint is the current context from `docker context ls --format json`, read as one object per line (Docker 23 and later) or as one array (Podman and podman-docker); Docker before 23 falls back to `docker context inspect`. A missing socket, an unsupported endpoint such as SSH, or unrecognized output stops the run with an explanation and the suggestion to set `DOCKER_HOST`. SIGINT, SIGTERM, uncaught exceptions and unhandled rejections close owned resources through the same idempotent cleanup scope, including acquisitions still in progress. A failure raised while cleanup is running is logged, not discarded, and a second SIGINT/SIGTERM exits immediately. Playwright SIGINT/SIGTERM handlers are disabled so they cannot exit before the cleanup scope finishes. Cleanup checks process-group liveness independently of the leader: it waits and retains SIGKILL escalation until the group disappears, including after the leader is reaped. The first ESRCH ends all signalling for that owned group. Failed helper startup/JSON and failed re-attachment terminate at the actual failure before dependent probes run. The isolated server starts through `scripts/dev.mjs` with the engine already configured, so the development Podman bootstrap is not used; `npm run dev` itself is unchanged by this harness. A container's first build can require several minutes and network access.

`--check` validates the registry/table and reruns both targets in a new temporary output directory, requiring byte-identical `baseline.json` for the same available capability profile. Host PID 1 names and `/proc/1/exe` read errors live in `linux-evidence.json`, outside comparison signatures. When mount namespaces or subordinate mappings are unavailable, the runner produces explicit skips; those are a different capability profile, not a matching reproduction of the complete Linux reference. `--check --recorded` only checks saved artifacts and does not test the current runtime. Each fresh rerun has its own process group: a terminal Ctrl-C reaches `--check`, which passes it to the running rerun once, lets that rerun's cleanup finish, and then prints the retained directory. `--check` works from any working directory and with an `--out` directory that has no difference registry.

The explicit native regression gate, `node scripts/conformance/check-native.mjs`, exercises actual busy unmount followed by `MNT_DETACH`, partial mappings (including a real 10,000-ID mapping), denied `setgroups`, the no-namespace fallback, symlinked/private `TMPDIR` (including successful two-creator parity), probe-owned cloud skips without alias side effects, injected detach/re-attach failures with retained rows and no stacked bind mounts, and a single timed stat without a parent stat. It requires rootless namespaces and `strace`. It builds the probe once and skips all latency sampling. Routine `npm test` runs report/fixture/lifecycle tests and the conformance/xtask Rust unit tests without launching measurements. The native gate exercises the probe-owned `no-mounts` mode directly through the runner. `node scripts/conformance/check-browser.mjs` uses the runner’s exact directory-selection helper and persistent-profile launch options, including DISPLAY removal, CDP detach, explicit click and read/write permission request. It verifies the real handle has a write grant and that the drop cannot reach the upload listener.

Use `--out /tmp/my-compat` on both target commands to write another result set without changing the committed results. Relative `--out DIR` and `--out=DIR` paths resolve from the caller’s directory. `--report` regenerates the Markdown table after reviewing the difference registry. Do not automatically approve new observations: each entry needs an owning #44 sub-issue (or an explicit permanent provider limitation) and a reason.

## Evidence and comparison

- `baseline.json` contains the normalized JSON lines from the program and script observations, grouped by target/filesystem in schema 2, with a separate `process: {linux, os}` section for the three runtime facts. The program emits every attempted step with a call and either `ok`, an errno name, or an explicit skip. IDs are equality observations, owners/groups are compared with the calling account and parent directory, and paths in cwd results use `$ROOT`. There are no raw PIDs, timestamps, randomized source paths or credentials in this file.
- `matrix.md` is generated from those observations, including successful steps, failures and skips. A skip is incomparable, never a passing result. A missing profile/case or duplicate step fails validation.
- `expected-differences.toml` explicitly lists each differing case/filesystem and a signature of both traces. An unlisted difference, a changed trace, or a listed difference that disappears fails the check. `[[observation]]` entries separately track facts without a comparable Linux fixture: they fail on changed evidence or reclassification, but do not claim automatic convergence. Later steps must review changed evidence and delete compatibility entries as their differences disappear. Allowed follow-up issue IDs are data in `follow-up-issues.json`; add newly created #44 sub-issues there rather than editing validator code.
- `evidence.json` and `linux-evidence.json` record the checkout `HEAD` and dirty flag captured before the run, without requiring any remote-tracking ref. They also record browser/host details and source-fragment presence used to attribute startup and flush behavior. The unrelated `.worktrees/` and only six generated files in the resolved output directory (`baseline.json`, both latency JSON files, both evidence JSON files and `matrix.md`) are excluded from the source dirty flag. The writers, reader/check and provenance exclusion share one generatedFiles filename registry. Hand-maintained inputs including `expected-differences.toml`, `follow-up-issues.json`, README and review notes still count as dirty, including untracked files and `--out` at the repository root. Exclusions are anchored at the repository root even when revision is queried from a subdirectory. Non-JSON held-probe output is retained in contextual auxiliary diagnostics while the trace preserves valid rows and an explicit output skip. Host startup details retain the actual read error code. Essential `baseline.json` is saved before the auxiliary timing/evidence files. Source inspection is labeled separately from executable observations; a changed source fragment is recorded rather than blocking measurement.
- `latency.json` and `linux-latency.json` keep noisy measurements separate from deterministic behavior. Cold means the first invocation of that operation in the fresh profile/filesystem; warm means its immediate repeat. These measurements do not evict host, provider or browser caches. Both probe binaries and the Linux local-helper provider use release builds. File operations include executable launch and return. Shell timing ends at the first interactive shell prompt; `ls -l /usr/bin` measures the shared system tree from each filesystem cwd. The stat operation makes exactly one `platform::stat` call on the target eight components below the test root; ownership-comparison parent stats are outside the latency operation; reads/writes transfer 1 MiB. Both runners validate latency preparation before timing begins and preserve its original errno if setup fails.

The same Rust source uses native libc/filesystem calls on Linux and WASI preview 1 plus the existing `os-posix` adapter on OS. WASIX `chdir`/`getcwd` imports observe the runtime cwd rather than maintaining a test-side cwd. ACL adapters encode the same entries in Linux's binary xattr format and the existing OS JSON xattr format. Path identity reads the ABI `Stat` result, and missing `dev`/`ino` is explicit. This ABI has no `Fstat` call and its raw descriptors differ from libc descriptors: retained-fd identity therefore uses the Preview 1 inode only when nonzero, and marks device identity unavailable because `writeFilestat` fabricates dev=1. The before and after descriptor identity calls have separate outcome rows; a failed call is attributed to its actual phase, and the identity relation is skipped unless both calls succeed. Raw missing values never claim equality. `same` requires both device and inode evidence for identity results. A structured unavailable marker remains incomparable, including colliding inode numbers across mounts; no field is dropped to claim equality. Trace steps use fixed code-unit ordering before signatures are computed, independent of Node/ICU collation. No unsupported syscall is emulated. All ABI errno names and common interrupted-call, memory, quota and disconnected-socket errnos are normalized; Preview 1 has no ENODATA number (the runtime aliases it to ENOENT), so ENODATA is preserved only where the named ABI exposes it. Unknown errors do not use Rust `ErrorKind` debug strings.

On non-Linux/non-WASI hosts, the workspace builds a small executable that reports the unsupported reference target and exits; it does not compile Linux-only adapters. Native workspace Clippy and `cargo clippy -p os-conformance --target wasm32-wasip1 --all-targets -- -D warnings` include test targets. Linux shell timing clears `ENV` so an interactive startup file cannot replace the measured prompt.

## Profiles and limits

The five OS profiles are an authenticated account's cloud home, OPFS browser storage, a real host-backed `FileSystemDirectoryHandle` acquired with Chromium CDP drag selection, a real Linux `os-local-helper` process, and a shared mount forced through the relay (`p2p: false`, with transport inspection). The host directory is not replaced by OPFS or a mock. The directory profile uses full Chromium with a fresh persistent profile's file-system read/write guard set to allow, then explicitly selects only the disposable fixture via CDP. A capture-phase drop listener stops propagation before the application can interpret the selection as an upload. Other accounts use separate incognito profiles. These are real host-backed handles and bytes; this is not manual native-picker coverage. Chromium's [permission-context implementation](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/file_system_access/chrome_file_system_access_permission_context.cc) documents the allow guard used for this fixture.

Linux uses actual bind mounts of one source and a separate tmpfs for cross-mount operations. On OS, primary and alias intentionally attach one tree. Browser storage uses the cloud tree as its distinct crossing target; other profiles use separate OPFS storage. Source-only marker files verify isolation before crossing observations are collected. The namespace ends with the process. When namespaces or subordinate mappings are unavailable, the runner records why those cases could not run. The Rust probe owns the `no-mounts` mode: it emits explicit skips at each mount-dependent operation group without attempting the operation. The `basic-cloud` mode similarly emits alias, mount-parent, remount and held-unmount skips before attempting unsupported attachment operations. The JS runner does not maintain a second skip list or discard attempted observations. Two mapped Linux users and two authenticated OS accounts create files under a setgid directory with a default ACL and umask 027. Both targets use exactly one neutral supplementary group, also the directory group, distinct from both primary groups. The native parent enters the mounted fixture before forking; children use relative paths and never traverse unrelated private TMPDIR ancestors. Native children first clear inherited groups, install only group 3, then drop privileges and verify credentials; inability to clear groups is an explicit skip. OS fixture accounts have their supplementary memberships replaced through the admin API before login. The owner changes the directory group through the ordinary chown call, then sets its setgid mode. This matches the native fixture and lets both creators demonstrate inheritance without elevating private mount access. Both targets record the actual directory mode/group and supplementary-group state. Where creator and directory groups coincide (the single-account creation case), inheritance is explicitly unavailable, not inferred from equality. The process caches its immutable group-map capability once. Any mapping that excludes group 65534 skips the named ACL operations and their dependent observations, including the entire two-account fixture before its default ACL is installed. The Linux temporary root is canonicalized before cwd comparisons. For private providers, the second account accesses the same tree through the existing authenticated export path, since private workspaces are account-scoped. This extra transport is part of the recorded current behavior.

Cloud alias/remount/unmount operations have no corresponding attachment API today and are explicitly unavailable. `chroot`, `mount`, and `umount` are absent from the OS syscall ABI; the runner records that fact instead of pretending the GUI mount method implements them. An exhaustive match against the actual `abi::Call` type makes any added/renamed variant fail probe compilation until its unsupported-call audit is reviewed; comments, enum placement and impl layout are not parsed. `node scripts/conformance/check-abi.mjs` checks the audit with a copy of the ABI crate built from its real manifest, inside a workspace made from the repository's own workspace manifest and lockfile, so dependencies, features, build scripts and workspace inheritance resolve as in the repository. Ordinary impl, comment, feature, build-script and dependency changes must compile; new `MountTree`/`Pivot` variants must fail the audit. Provider unmount lifetime is tested separately by pausing a live executable on stdin, detaching its mount, then resuming its retained descriptor or cwd operations. Linux first records ordinary `umount` (EBUSY), then actually performs `umount2(MNT_DETACH)` before reading the retained fd or asking for cwd. OS records its existing `unmountLocal` detach and explicitly marks the absent separate busy-unmount API. Linux re-attaches if either ordinary unmount or lazy detach succeeded. Both references re-attach before the next case; re-attach failure is recorded and aborts the fixture. On the OS each held case has three deadlines, 60 seconds each: reaching the barrier, the runner's detach, and finishing after the runner resumes the probe. A timeout is recorded in the step for its phase (`barrier`, `detach` or `completion`). A probe cancelled in any phase must exit within a further 30 seconds before anything touches the mount again. A detach that does not finish, or a cancelled probe that does not exit, saves the rows and stops the fixture rather than re-attaching over an unknown mount state.

The native host is headless: it has no corresponding four GUI applications or browser OS tabs. Those Linux process-profile rows explicitly state that limitation. OS script observations assert that the actual built-in applications opened, inspect processes and PID 1, and test cross-tab visibility with a live process, comparing PID, executable path and argv together. Startup readiness errors remain visible alongside any subsequent cleanup failure. The trace omits redundant constant app-open flags and records the measured process images. The fixture waits for its completed `cat /proc/1/cmdline` process to be reaped before taking the idle Files snapshot. Startup ownership comes from live init/login leases and a real managed supervisor process launched for this fixture; source-fragment attribution is auxiliary evidence only. These process facts are `[[observation]]` records, not permanent Linux differences; no Linux GUI behavior is fabricated to make the comparison pass. This is an L0 baseline, not a GUI protocol gate or a claim of full POSIX compatibility.
