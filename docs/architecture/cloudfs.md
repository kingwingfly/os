# Cloud filesystem v2

L1a part 2 of [#48](https://github.com/kingwingfly/os/issues/48) implements contract §2.3 at the authority and in the portable `os_vfs::cloud::CloudFs` driver. The browser syscall path still uses the existing path protocol. Client integration and its host HTTP transport are subsequent work; there is no compatibility window once repository callers move.

## Calls and identity

`abi::fs` owns the shared handle, metadata, open-option and lock values. `os-vfs` reexports them. `abi::remote_fs` defines the version-2 JSON envelope and calls. `POST /api/fs` accepts `version`, `credential`, `session` and `call`. A wrong version returns `EPROTONOSUPPORT`; no uid, PID, instance ID or caller-supplied pathname is accepted as authority. Control bodies are limited to 4 MiB. The outer Worker requires an `Origin` header matching the service origin for POST requests.

`connect` requires a valid, cloud-enabled process credential in the request's authenticated namespace. The service returns its filesystem ID, signed root handle, capability profile and a fresh session ID/resume secret. Separate connections get separate handle proofs even if they share an account or cookie. Subsequent calls authenticate the secret and a credential in the recorded issuer namespace; cookies are unnecessary for resuming. Job credentials return `EACCES` at connect and on every control/data call, including existing sessions: they must use the existing path/job gateways that enforce `device_tasks.grants`. Handle-scoped job delegation remains unsupported. This uses the current credential issuer until the instance bootstrap work replaces it.

A handle's HMAC covers filesystem, session and inode identity. It grants no permission and keeps no reference. Inode numbers use SQLite AUTOINCREMENT, never recycle, and have generation 1. Missing objects are `ESTALE`; altered or foreign-session handles are `EACCES`. Lookup uses the inode's recorded name and the indexed child name, checking search permission. Walk checks all components before resolving any and stops at missing names, links or non-directories. It never interprets `..` or crosses a mount.

Open descriptions record their service session, inode and access; `vfs_open_grants` records their retaining credentials. Exec copies existing grants to its replacement credential before retiring the old token, provided cloud access is retained. A fork holding the old credential keeps its grant independently; descriptions opened after a sibling exec are not retroactively inherited. Each request authenticates a presenting credential; open operations also require a live retaining grant in the session namespace. Writes and truncation apply privilege-bit removal using the presenting credential, independently of who opened the reference. Chmod does not remove an existing grant. Revocation/expiry removes that credential’s grants. Losing the final grant ends its references and locks and leaves an `EACCES` tombstone until release or session cleanup. Retired tokens remain invalid for new requests; an exec that drops cloud access cannot inherit grants. Path-only opens retain removed directories without granting byte access.

The `create`, `mkdir` and `mknod` calls require the current process's `umask`, including an explicit zero. The driver sends it separately from the requested mode so the authority can apply the parent's default ACL and setgid inheritance. Changing the mask takes effect on the next creation using the same issued credential. Creation accepts read, write or read/write access; exec and path access return `EINVAL` before changing names or opening existing files. Truncate-on-open applies only to existing files: a newly created empty file keeps its creation metadata and privilege bits.

Creating or renaming into an absent account home requires its owner or root, even in a writable parent. Moving a directory between parents also requires write permission on that directory. Renaming a registered home or a directory containing one returns `EBUSY`, including for root and for homes not created yet; `usermod -d HOME -m NAME` moves an existing home and updates its account record together.

Device creation through v2 requires root and an unused name. The `present` and `snd` drivers create their nodes, live state and expiry together in their respective `/dev` directories; other driver names return `EOPNOTSUPP`. Unlinking an interactive device uses its driver's ownership checks and teardown, releasing attached descriptors, voices and pending requests and notifying followers. Device hardlinks, direct renames and replacements by rename are refused with `EPERM` while drivers identify devices by pathname.

## Lifetime and cancellation

The lease is 120 seconds. Hosts call `renew` at least every minute, including while operations are pending. Renewing with the existing secret resumes all opens and locks; no in-memory authority state is needed. Explicit disconnect or expiry releases references, locks and active read manifests. Credential revocation is independent of browser logout.

Open/create calls carry unique tickets. Successful replies are retained for idempotent delivery. `cancel_open` records cancellation even when it arrives before the original request, and releases a delivered-but-abandoned result. Lock tickets similarly identify persistent waits; the driver acknowledges each grant to retire its wait record; cancellation also removes a grant whose reply the client abandoned. POSIX wait cycles are checked across inodes; flock and POSIX locks never conflict. Compatible adjacent or overlapping ranges with the same cancellation ticket coalesce in storage. Different tickets retain their own surviving pieces so late cancellation cannot unlock another request; conflict queries report the complete contiguous range for the same owner, family and kind. Granted locks belong to open descriptions and disappear on release.

The portable driver starts operations only when polled. Its cancellation guards retain cleanup across a dropped future or disconnected transport. A release is retained before draining earlier cleanup, so an earlier failure cannot lose a reference consumed by `FileRef::close` or its release queue. Hosts must drain both queues. `renew` and ordinary driver calls drain deferred cleanup first.

For each byte operation and open-reference control call (metadata, truncate, sync and locks), `Transport::caller` snapshots the current kernel task's credential before any await. Byte operations also snapshot its PID; neither the connection nor the open description supplies a cached calling identity. `FileRef::metadata` and `SEEK_END` use `open_metadata`, which authenticates the current caller and validates the retained open grant; ordinary handle metadata continues to use its explicit credential. Lock polling and acknowledgement keep the same acting credential. The driver retains the original opening credential for deferred cancellation/release, allowing cleanup after the acting task disappears. If exec retired that token, cleanup retries with a snapshot of the current caller. Authentication failure retains the cleanup obligation for a later authorized caller. Authorized cleanup can retire revoked opens and their already-cancelled locks without restoring access. Session expiry is the final cleanup when the host disappears. Session secrets and request/lock tickets belong in private kernel state.

## Bytes and commits

`POST /api/fs/data` carries the serialized `DataRequest` in `X-OS-Filesystem`. Reads return raw bytes; writes send raw bytes and return `Written { offset, len }`. Individual data calls are limited to 8 MiB; the portable driver may return a short read/write at that boundary. Offsets and sizes obey the signed 64-bit limit, including EOF validation. SQLite bindings and reads preserve integers beyond JavaScript's safe-number range.

The gateway authorizes through the binding, applies process I/O accounting, and streams immutable data to or from R2 outside authority WASM. Each data request includes the calling `pid`, which the process registry validates against the presenting credential and its issuer namespace, including for empty transfers. Forked processes share a credential but retain their own I/O budgets; missing PIDs are rejected. A write commits only after R2 acknowledges the complete object and the authority revalidates the session, opener and presenting credential. The transaction splices its extent into the inode's current manifest. Append chooses the current EOF in that same transaction, so concurrent appends cannot overwrite each other. A lost write response is uncertain; transports must not silently replay writes.

Truncation clips extents without copying data; later growth reads as zero. Reads pin their immutable manifest until stream completion/cancellation, with the service lease covering host loss. If I/O accounting denies a prepared request, the gateway releases its read pin or upload reservation before returning the denial. Existing chunk files can become extent manifests without moving their bytes, and source files stay pinned while their extents are referenced. Ordinary files cloned from build/image assets retain immutable asset references through reads and partial writes, with asset integrity checks preserved. The existing inline `pread` reader and file/job gateways understand these content representations, including sparse holes. Removing the final name or open reference permits collection; retained readers, jobs and shared extents delay it. Ordinary-file collection never deletes release assets.

Completed writes already reached the R2 plus SQLite service commit point. `sync_all`/`sync_data` validate the open and acknowledge that point. This does not claim host `fsync` behavior or finish the broader #50 consistency gates.

## State and validation

Schema 9 records durable service sessions, open descriptions with independent retaining grants, cancellation receipts, lock queues, immutable extents and temporary read/upload references. Older state is refused without migration. Image and browser release checks require the same schema. No deployment is part of this change.

`crates/vfs/tests/cloud.rs` exercises cancellation and durable lock state without host dependencies. `tests/cloudfs.spec.js` exercises the real Worker/SQLite/R2 path: forged/foreign/stale handles, permission and open-grant rules, cancellation races, descriptor metadata and seeking after exec, merged POSIX ranges with independent cancellation, exec/fork grant retention and revocation, sparse bytes and large offsets, atomic append, locks, revocation and actual lease expiry. `node --test tests/cloudfs-authority.mjs` uses the built Worker with disposable bindings and SQLite to check job denials on connect, existing-session controls, data preparation and commit, alongside the existing path-grant restrictions. Full client/host adapter conformance and latency measurements remain #48 work.
