# Browser-backed filesystems (OPFS and directory handle)

[#48](https://github.com/kingwingfly/os/issues/48), [#49](https://github.com/kingwingfly/os/issues/49) and [#50](https://github.com/kingwingfly/os/issues/50) implement contract §2.2, §2.5, §2.6, §2.12, §3 and §5 for Origin Private File System (`os-workspace`) and browser `FileSystemDirectoryHandle` attachments. Portable filesystem, permission, link, durability and advisory-lock rules live in `os_vfs::hostfs::HostFs` and the Wasm `LocalMount` facade (`crates/client-kernel/src/{mounts.rs,hostfs.rs}`). `web/kernel/fs-store.js` is strictly the host I/O, IndexedDB and Web Locks adapter; the legacy in-memory `PermissionMount` (`web/kernel/mount-policy.js`) and `os_kernel::mount_policy` are removed.

## Identity, metadata stores and format versioning

Each OPFS workspace (`os-workspace`, or another distinct top-level OPFS directory outside `os-orphans`; mounting OPFS root, `os-orphans`, or nested OPFS subdirectories is refused with `EACCES`) mints one profile-local UUID under the `os-fs-mint` Web Lock, stores it inside the `StoreHeader` of IndexedDB database `os-fs-opfs:<storeKey>` (default `os-fs-opfs:os-workspace`), and reports `FsId("opfs:<uuid>")` (`profiles::OPFS`). Each attached browser directory handle resolves or mints its UUID under `os-fs-mint` in `os-fs-handles` by comparing stored handles with `FileSystemHandle.isSameEntry` and rejecting ancestor/descendant overlaps via `resolve()` (`EACCES`), persisting metadata in `os-fs-dir:<uuid>` (`FsId("hostfs:<uuid>")`, `profiles::DIRECTORY_HANDLE`). No sidecar files are ever written into a user's host folder.

`FsId::dev()` and every minted `NodeId.ino` are masked to the 53-bit JavaScript safe-integer range (`1..=0x1F_FFFF_FFFF_FFFF`), keeping `st_dev`, `st_ino` and directory `d_ino` exact across Rust, JSON and Wasm boundaries and identical across mount aliases, remounts and tabs of the same browser profile. Inode records are serialized by Rust as JSON strings in IndexedDB so nanosecond timestamps never pass through lossy JavaScript `Number` parsing.

OPFS persists owner, mode, access and default POSIX ACLs, `user.*` extended attributes, setgid inheritance and creation `umask` behavior across tabs and remounts. Directory-handle inodes bind metadata to `(path, HostFingerprint { size, mtime_ns })` recorded at the last OS mutation. When host-side edits, replacements or renames change the fingerprint outside the OS, open descriptors targeting the old state fail with `ESTALE` and subsequent path resolution mints a fresh inode ID with private default permissions owned by the attaching account (`0600`/`0700`, `0700` when `execute` is granted and a file begins with the `\0asm` header) and no stale ACLs. Browser handle `readOnly` and `execute` grants remain hard ceilings; revoking browser permission (`queryPermission !== 'granted'`) fails with `EACCES` and detaches the mount.

Every store header carries `STORE_FORMAT_VERSION = 3` in `meta["version"]` (§2.12), plus a durable `pending_rename` recovery record when staging OPFS replacements. An older or missing format version clears `inodes` and `locks` once and reinitializes root metadata to private defaults without deleting or modifying any OPFS or host user files. A newer format version written by a newer release in another tab is left untouched and fails attachment and operations with `EPROTONOSUPPORT`. Snapshot file selections (`mount_snapshot`) run in memory over `HostFs::opfs` (`SimProfile`) with data/namespace writes refused as `EROFS` while allowing owner in-memory permission/ACL setup for peer export sharing.

## Namespace, open-unlink, links and durability

Namespace mutations, `O_EXCL` creation and `RENAME_NOREPLACE` serialize across tabs under the profile-wide `os-fs-ns:<uuid>` Web Lock (failing closed with `ENOLCK` if Web Locks is unavailable or rejects). On OPFS, both ordinary `rename` and `RENAME_NOREPLACE` execute atomically under `os-fs-ns:<uuid>` with durable `pending_rename` staging and orphan preservation if a tab crashes or commit fails mid-replace; on directory handles, `RENAME_NOREPLACE` checks target absence under `os-fs-ns:<uuid>` and falls back to recursive copy-and-remove when `FileSystemHandle.move` is unavailable on directories, refreshing recorded child fingerprints.

Each open file description holds an exclusive `os-fs-open:<uuid>:<ino>:<open_id>` Web Lock for its lifetime. On OPFS:
- Hard links (`link`) share a single `InodeRecord` and backing path across multiple directory entries, maintaining live `nlink`.
- Symbolic links (`symlink`, `readlink`, `O_NOFOLLOW`) store link targets in IndexedDB (`Backing::MetaOnly`); symlink targets escaping the mount root or a narrowed shared export boundary fail closed with `ELOOP`.
- Unlinking the final name while any tab holds an `os-fs-open:<uuid>:<ino>:*` Web Lock moves the backing file to `/os-orphans/<uuid>/<ino>` (`Backing::Orphan`), removes the directory entry immediately, reports `nlink == 0` on `fstat`, and deletes the orphan plus inode record when the last tab closes its descriptor. On startup/mount, `HostFs::opfs` queries `navigator.locks.query()` for active `os-fs-open:<uuid>:<ino>:*` locks on every entry in `/os-orphans/<uuid>`, repairs/preserves any entry whose persisted metadata still shows `nlink > 0` or `pending_rename`, and sweeps true orphans left behind by crashed tabs whose Web Locks were released by the browser.

On directory handles, `link` and `symlink` are refused explicitly with `EPERM`, open descriptors survive OS-initiated `rename`, and unlinking an open file marks its inode stale (`ESTALE` on subsequent descriptor I/O).

Writes commit through exclusive `FileSystemWritableFileStream` swaps (`QuotaExceededError` mapped to `EDQUOT`). `fsync` and `fdatasync` validate descriptor state (`EBADF` on closed/invalid descriptors, `EINVAL` on non-syncable descriptors); on OPFS they flush the backing sync access handle (`createSyncAccessHandle().flush()`) and sync IndexedDB with `durability: "strict"`, while on directory handles they honor the declared `WritableClose` durability point by verifying the retained host entry/fingerprint against outside tampering and syncing IndexedDB with `durability: "strict"` (surfacing failures as `EIO`).

## Profile-wide advisory locks

`flock` whole-file locks and `fcntl` (`F_SETLK`, `F_SETLKW`, `F_GETLK`) byte-range locks are independent lock families coordinated across all tabs of the browser profile under `os-fs-lock:<uuid>` and persisted in the `locks` object store keyed by `ino`. Each open file description receives a sequential `open_id` stored in `StoreHeader` and holds an exclusive `os-fs-open:<uuid>:<ino>:<open_id>` Web Lock while alive, while each active blocking wait holds `os-fs-wait:<uuid>:<ino>:<open_id>:<ticket>`.

Before reading or mutating lock records, `HostFs` queries `navigator.locks.query()` to prune any held locks or queued waits whose `os-fs-open:<uuid>:<ino>:<open_id>` or `os-fs-wait:<uuid>:<ino>:<open_id>:<ticket>` Web Lock was released by a crashed tab or cancelled call. Non-blocking conflicts return `EAGAIN`. Blocking `F_SETLKW` / `flock` waits record a waiter edge in IndexedDB, check multi-inode `fcntl` wait-for graphs to reject cycles immediately with `EDEADLK`, arm shared `os-fs-open:<uuid>:<ino>:<blocker>` Web Lock and `BroadcastChannel("os-fs-locks")` listeners before releasing `os-fs-lock:<uuid>` so no wakeup can be lost across tabs, and clean up waiter records on cancellation, descriptor close, unmount or tab termination. If `navigator.locks` is unavailable or fails, `HostFs` fails closed with `ENOLCK`.
